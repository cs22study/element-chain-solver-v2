# 原作者專案分析與計算原理 (Original Algorithm & Design Analysis)

## 1. 遊戲背景與核心規則 (Game Rules)

「元素連鎖」為《神魔之塔》中出現的熱門益智小遊戲，規則如下：
1. **盤面規格**：$5 \times 5$ 共 25 格，包含 5 種屬性卡片：水 (0)、火 (1)、木 (2)、光 (3)、暗 (4)。
2. **操作機制**：玩家在每一步中，只能**點擊並消除 1 張卡片**。
3. **掉落補牌**：
   - 點擊該卡片消除後，上方現存卡片在重力作用下向下掉落補位。
   - 頂部產生的空缺，由隨機補進的新卡片補滿（5 種屬性出現機率通常均等）。
4. **連鎖消除機制 (Cascade Matching)**：
   - 補滿後，盤面上任何在**橫向或直向連續達 3 張（或以上）**相同屬性的卡片會自動消除。
   - T 字形、十字形、L 字形等直線交會會合併判定消除。
   - ⚠️ **重要例外**：$2 \times 2$ 方塊狀（無直向或橫向 3 連線者）**不構成消除**。
   - 消除後空位再次因重力掉落，頂部再次隨機補滿，若又有 3 連線則觸發下一輪連鎖消除，直到無任何 3 連線為止。
5. **計分標準**：
   - 評分目標為「平均每一步的消除總張數」最高（$\text{Score} = \frac{\text{總消除張數}}{\text{步數}}$）。
   - 每一步點擊後盤面均會變動，適應性策略（Adaptive Strategy）為：每步點完後依據新盤面重新挑選最優解。

## 2. 演算法設計與數學計算原理 (Mathematical Modeling)

本專案採**有限時界馬可夫決策過程 (Finite-Horizon MDP)** 與**動態規劃 (Bellman Equation)** 來求取各起手點的期望消除得分。

### 2.1 狀態與動作定義
- **狀態 (State $s$)**：長度 25 的陣列，值為 $0 \sim 4$（各格顏色屬性）。
- **動作 (Action $a$)**：點選位置 $a \in \{0, 1, \dots, 24\}$。
- **規劃深度 (Planning Horizon $H$)**：通常設為 2 步（預設）、3 步或 4 步。

### 2.2 轉移與擴展 (`expand(board, a, R)`)
當在盤面 $s$ 執行動作 $a$ 時：
1. 目標格設為 $-1$（空格）。
2. `gravity()` 讓上方非空格下落，統計頂部空缺數 $n$（通常 $1 \le n \le 5$）。
3. **補牌取樣策略 (Hybrid Sampling Strategy)**：
   - **精確枚舉 ($n \le 2$)**：$5^n \le 25$ 種補牌組合，窮舉所有可能性，精確機率 $p = \prod \text{weights}[d]$。
   - **隨機取樣 ($n > 2$)**：隨機產生 $S=20$ 組補牌樣本，每組權重 $p = \frac{1}{S}$。
4. **連鎖模擬 (`cascade()`)**：
   - 重複檢測 3 連線與掉落。
   - 若發生隨機補牌，以重複模擬次數 $R$（$H=2$ 時 $R=100$；$H=3$ 時 $R=4$；$H=4$ 時 $R=1$）取平均期望消除數。
   - 保守估計開關 (`IGN=1`)：純粹由全新補進之卡片自然湊成的 3 連線**不列入計分**，僅計算與原留在盤面卡片串接之連鎖，避免過度樂觀估計。

### 2.3 期望值與貝爾曼最優方程 (`vals(board, H)`)
定義 $V_h(s)$ 為在狀態 $s$ 下，剩餘可走 $h$ 步時的最大期望總消除量：
$$V_h(s) = \max_{a \in \{0..24\}} \mathbb{E}_{s' \sim P(\cdot|s,a)} \left[ \text{Removed}(s,a) + V_{h-1}(s') \right]$$
基底條件：$V_0(s) = 0$。

對初始盤面 $s_0$ 的每個候選起手點 $a$：
$$Q(a, h) = \mathbb{E}_{s'} \left[ \text{Removed}(s_0, a) + V_{h-1}(s') \right]$$
各起手點之最終推薦分數為：
$$\text{BestScore}(a) = \max_{h \in [1..H]} \frac{Q(a, h)}{h}$$
$$\text{BestStep}(a) = \arg\max_{h \in [1..H]} \frac{Q(a, h)}{h}$$

此設計能完美捕捉「第 1 步先蓄勢佈局、第 2 步爆發大消除」的長遠價值策略！

### 2.4 記憶化與剪枝 (Memoization)
利用 `memo = new Map()` 將 `H:board_string` 的最佳值向量儲存，大幅減少重複子盤面的運算開銷。

## 3. 截圖自動辨識與電腦視覺原理 (Computer Vision)

原作者設計了極為輕量、不需任何外部深度學習函式庫（如 OpenCV 或 Tesseract）的純原生 JavaScript CV 演算法：

### 3.1 色彩分類器 (HSV Classification)
- 將 RGB 轉為 HSV 色彩空間：
  - 排除低飽和度 ($s < 0.45$) 或低亮度 ($v < 0.45$) 之無效像素。
  - 色相區間判定：
    - **水** (Blue)：$180^\circ \le h < 245^\circ$
    - **木** (Green)：$75^\circ \le h < 175^\circ$
    - **光** (Yellow)：$38^\circ \le h < 75^\circ$
    - **暗** (Purple)：$245^\circ \le h < 340^\circ$
    - **火** (Red)：其他區間 ($340^\circ \sim 360^\circ$ 及 $0^\circ \sim 38^\circ$)

### 3.2 盤面定位與格線聚類 (`detectGrid`)
1. **降解析度採樣**：將螢幕截圖寬度縮放至 520px 以內以保證毫秒級效能。
2. **面板背景分割**：偵測遊戲盤面深藍色外框 ($200^\circ \le h < 255^\circ, s>0.3, 0.1<v<0.5$)。
3. **連通區域分析 (`labelComps`)**：使用 DFS/BFS 標記不相交連通像素區塊。
4. **形態學侵蝕 (Erosion, $E=2$)**：腐蝕邊界去除卡片間細微雜訊與裝飾線條，防止相鄰卡片粘連。
5. **卡片輪廓過濾**：篩選長寬比接近正方形 ($0.75 \sim 1.33$) 且面積佔比合理的方塊。
6. **座標聚類 (1D Clustering)**：對候選方塊之 X、Y 座標進行密度分群，檢驗是否形成等距之 5 行與 5 列。

### 3.3 互動式 Canvas 容錯校正
若自動識別失敗或有局部偏差，系統提供 Canvas 拖曳介面：
- 使用者可直接以觸控或滑鼠拖曳左上角/右下角錨點縮放，或拖曳框體整體移動。
- 採用 Pointer Events 與 `setPointerCapture`，移動時即時重繪並更新 25 格屬性。

## 4. 現有程式碼之優缺點分析

### 優點 (Strengths)
1. **純前端單檔部署**：無任何外部依賴，速度極快，零伺服器費用。
2. **多執行緒設計**：核心算法封裝於 Web Worker，計算時 UI 不會卡頓凍結，有即時進度條。
3. **精巧的動態規劃與模擬**：適應性決策模型非常符合玩家真實心理（看到盤面再選下一手）。
4. **色彩自動定位設計**：無需伺服器上傳即可辨識手機截圖。

### 可優化與潛在改進空間 (Improvement Opportunities)
1. **遊戲不同解析度與光暈適應性**：部分神魔之塔活動關卡盤面背景或卡片有特殊特效（如流光、燃燒符石、黑白符石、鎖定符石），目前 HSV 固定閾值可能誤判。
2. **手機版 UI 與手勢體驗**：
   - 調色盤筆刷按鈕在單手操作時略顯侷促。
   - 缺乏「一鍵重設盤面」、「上一動復原 (Undo)」。
3. **PWA 支援度**：目前無 `manifest.json` 與 Service Worker，無法一鍵加入手機主畫面離線使用。
4. **國際化與多語言**：目前僅有繁體中文，可考慮語言切換。
5. **歷史記錄與雲端備份**：若使用者需要儲存特殊盤面或分享給戰友，可透過 Google Apps Script 免費 API 串接雲端備份。
